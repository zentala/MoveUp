3. Behaviour & interactions

  • Navigation: ◀ ▶ jump 1 day · click date → date picker · ← / → arrow keys · home/end = range bounds.
  • Scroll: horizontal wheel/touchpad drag through days. Snap to hour on release.
  • Now indicator: blue vertical line + dot, refreshed every 60s (only when selected day = today).
  • Sleep band: auto-detected ≥4h continuous Away between 22:00–08:00, rendered as soft purple block with moon glyph.
  • Late-night flag: red dot in header when last session ends after 00:00.
  • Hover tooltip: timestamp · state · duration of contiguous segment · score.
  • Click segment: cross-filters the sessions table below (selects that session row).
  • Click hour bar: shows tooltip "14:23 — Standing for 12 min".
  • Sleep band on no data: shows "?" indicator when retention doesn't cover the night.

4. Open questions — review these visually

Q1. Width of side previews (yesterday / tomorrow)
How much context do you want from neighbouring days? Trade-off: more sides = less hero space.
8% each (compact, only ~4h glance) 12% each (≈6h, recommended) 15% each (≈8h, generous) 20% each (≈10h, almost equal weight)
Q2. Snap target when scrolling stops
Where should the strip land when you release scroll? Affects how "discrete" the feel is.
No snap (free scroll, smooth) Snap to hour (subtle, predictable) Snap to day (strong, almost flipboard)
Q3. Color encoding intensity
Full-width strip will be visually dominant — 4 colours may shout.
Keep 4 colours (Sit / Stand / Walk / Away) — full info Reduce to 2 (Active / Away) — calmer, less info 3 colours (group Walking into Standing)
Q4. Sleep band on unknown / missing data
If retention doesn't cover 22:00–08:00, what to show?
Hide it (silent) Show with "?" glyph + hover "no data for this window" Show diagonal-hatch pattern as "uncertain"
Q5. Day / Week toggle — scope of this task or follow-up?
Should we ship a Week-view mode in the same task, or land Day first and iterate?
Day only this task; Week as follow-up (E012-T08) Day + Week toggle together Skip Week entirely — range picker handles multi-day already
Q6. (bonus) Where does Now indicator live across midnight?
If you're viewing today and it's 00:30, "now" is on the left edge — confusing?
Stays at real position (left edge after midnight) Auto-advance "selected day" at midnight so now is always central Show ghost marker at 24:00 on previous day + real one

5. Acceptance criteria (draft)

  • Component spans full container width.
  • Renders 1 hero day + ≈6h preview on each side (configurable via Q1).
  • Header ◀ / ▶ change day; keyboard ← → works on focus.
  • Now indicator visible when selected = today; auto-refreshes every 60s.
  • Every segment has tooltip (timestamp · state · duration).
  • Sits as the first box in ExplorerTab, above the KPI grid.
  • ≥80% test coverage on new component.
  • File ≤250 lines; split into DailyTimelineStrip.tsx + TimelineDayBand.tsx + TimelineHourAxis.tsx if needed.

B. Side-by-side diff vs. first proposal

Before (initial proposal)

  • Single hero strip only
  • Side previews 12% width = 6 h ⇒ 2× time distortion (fisheye)
  • Auto-flip selectedDay at 00:00 (UI jumps)
  • "Sleep" auto-band (Away ≥4h, 22:00–08:00) — false positives
  • Red dot "after midnight detected" — judgmental wording
  • Replaces StateGantt → loses multi-day pattern view
  • Range picker conflict unresolved
  • Click-segment cross-filter in scope

After (locked, 2 components)

  • Two components: DateNavigator (range + per-day list) + TimelineDetail (36 h hero)
  • Date Navigator merges range picker + day list — one card, one mental model
  • Per-day rows show % proportions (Sit/Stand/Walk/Away) — readable at glance
  • Stand hours + standing% as numerical totals on the right of each row
  • Weekend rows dimmed; today highlighted; future hours hatched
  • Proportional 36 h detail scale; honest side previews
  • No midnight jump · label auto-flips at 02:00 if no manual nav
  • No sleep band; honest "Away" + backlog item for sleep API
  • Cross-filter deferred (no sessions table yet)
